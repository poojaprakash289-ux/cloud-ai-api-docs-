GCP Lift-and-Shift Migration – User Guide

1. Document Overview

Purpose

This document provides a structured guide for performing lift-and-shift migration to Google Cloud Platform, outlining the steps required to move workloads with minimal changes while ensuring a secure and efficient transition.

Scope

This guide covers the end-to-end migration process, including environment setup, workload replication, migration execution, validation, and post-migration optimization.

Audience

Cloud engineers, DevOps teams, system administrators, and solution architects responsible for cloud migration.

Definitions / Acronyms

TermDefinition
Lift and Shift (Rehost)Moving applications without architectural changes
VMVirtual Machine
VPCVirtual Private Cloud
IAMIdentity and Access Management

CutoverFinal switch to cloud environment

2. Introduction

Lift-and-shift migration enables organizations to move workloads from on-premises infrastructure to the cloud without modifying application architecture, ensuring faster adoption and reduced complexity.

When to Use This Approach

  • When rapid cloud migration is required
  • When applications are stable and compatible
  • When minimal downtime is critical
  • When modernization is planned for a later phase

Key Benefits

  • Faster migration
  • Reduced complexity
  • Lower risk
  • Quick cloud adoption
  • Foundation for future optimization

3. Prerequisites

  • Active GCP account with billing enabled
  • IAM roles and permissions configured
  • Access to source infrastructure
  • Network connectivity between source and cloud
  • Required firewall ports open
  • Backup of critical workloads completed

4. Migration Architecture Overview

  • Source Environment: On-premises or existing infrastructure
  • Target Environment: Google Cloud Platform
  • Migration Service: Migrate to Virtual Machines
  • Connectivity: VPN or dedicated connection
  • Storage & Compute: Cloud-based VM instances and disks

5. Migration Workflow

Prepare → Configure → Replicate → Migrate → Validate → Optimize

6. Step-by-Step Procedure

Step 1: Create GCP Project

Create a project and enable billing in Google Cloud Platform.

Step 2: Configure IAM Access

Assign required roles and permissions to users and services.

Step 3: Enable Required APIs

Enable Compute Engine and migration-related services.

Step 4: Set Up Virtual Network

Create VPC, subnets, and define IP ranges.

Step 5: Configure Firewall Rules

Allow required inbound and outbound traffic.

Step 6: Establish Connectivity

Set up VPN or direct connection between source and cloud.

Step 7: Prepare Source Systems

Validate OS compatibility and clean up unused data.

Step 8: Configure Migration Service

Set up Migrate to Virtual Machines and create migration project.

Step 9: Register Source Environment

Add source infrastructure to migration service.

Step 10: Discover Workloads

Identify virtual machines and applications for migration.

Step 11: Select Workloads

Choose workloads and group into batches.

Step 12: Configure Replication

Define replication settings.

Step 13: Initiate Replication

Start data replication to cloud.

Step 14: Monitor Replication

Track progress and resolve issues.

Step 15: Perform Test Migration

Run test instance to validate workloads.

Step 16: Validate Test Results

Verify functionality and performance.

Step 17: Plan Migration Cutover

Schedule migration window.

Step 18: Execute Final Cutover

Stop source workloads and initiate migration.

Step 19: Launch Workloads in Cloud

Start virtual machines in cloud.

Step 20: Configure Workload Networking

Assign IPs and configure access.

Step 21: Update DNS Configuration

Redirect traffic to cloud workloads.

Step 22: Perform Post-Migration Validation

Verify applications and data integrity.

Step 23: Enable Monitoring and Logging

Set up monitoring tools and alerts.

Step 24: Optimize Resources

Right-size compute and storage.

Step 25: Configure Backup and DR

Enable backup and recovery strategies.

Step 26: Decommission Source Systems

Shut down legacy infrastructure.

7. Validation Checklist

  • All workloads migrated successfully
  • Applications functioning correctly
  • No data loss observed
  • Network connectivity verified
  • Monitoring enabled

9. Security Considerations

  • Encrypt data in transit and at rest
  • Implement IAM and RBAC controls
  • Secure network using firewall rules
  • Monitor logs for anomalies

10. Best Practices

  • Start with non-critical workloads
  • Perform test migration before cutover
  • Use phased migration approach
  • Continuously monitor performance

11. Post-Migration Activities

  • Perform performance tuning
  • Optimize cost and resource usage
  • Configure backup and disaster recovery
  • Document final architecture
